Signing in to a site that wants an authenticator code

Some sites ask for a 6-digit code from an authenticator after the password. This page shows what happens with no setup, the two ways to close the loop, and why the code cannot simply be taken from the password manager that already has it.

Why not take the code from the password manager that already has it?

Password managerHolds the setup key, shows the codes.
coincellNeeds the 6 digits.
✕
not possibleNo door between themThe system's password manager hands a code only to a person: you look at it, or you approve an autofill with your fingerprint or face. It offers other programs no command or interface to ask for one.
  • That is deliberate. If any program could ask for codes, so could any malware.
  • The only way around it would be to operate the password manager's window as if a person were clicking. coincell does not do that.

Why a second copy of the key works

An authenticator code is not sent by the site. It is arithmetic: setup key + current time → 6 digits, recomputed every 30 seconds. The site does the same sum and compares.

  • Anything holding the same key shows the same code at the same moment. Two holders do not conflict, and the site cannot tell which one produced a code.
  • So "a separate thing" is not a second authenticator account. It is the same key, kept in one more place.
  • The cost: on that computer, the password and the key for the second step then sit together in the Keychain. Someone who gets into that Keychain gets both. That is already true wherever one password manager holds both.
